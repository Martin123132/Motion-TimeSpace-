# Private replay sequence

All invocations run with the retained Windows Python 3.13, -B -u, numpy/scipy/mpmath/psutil, the pinned local common-clock CAMB source and compiler. The code refuses active owner holds inherited from the preceding stages. Work in a **fresh private sibling** under post-checkpoint-work with the same scripts and design documents; outputs are exclusive-create. No file from a sealed checkpoint needs deletion. Use at most two single-thread workers. Inputs and numerical settings are those of the preserved thermal/common-clock receipts. Do not start an unattended alternate route if a gate fails.

1. Run design.py before any low-bank acquisitions. The verification compares the design checksum and local issuance order; high-precision weighted minors are in weights.json. No flux measurements enter the design.
2. bank.py 1 <fine|coarse> seed on the unmodified engine originally encountered DVERK -3 (minimum step) in both attempts. It is unnecessary to repeat failed acquisitions for the scientific replay. diagnostic_build.py build trace or resolve creates a scoped native package and removes only its temporary compilation files. To reproduce the failure use diagnostic_build.py diagnose trace 1 fine seed; plan for a terminal error, not a valid spectrum.
3. Set MTS_PRIVATE_FLOOR in the *parent process* to 32 for fine or 512 for coarse. For each mesh run diagnostic_build.py diagnose resolve 1 MESH seed, then bridge, then source heavy 1200, source heavy 1500 and source cold 225 (same prefix). This permits a single bounded re-entry from the last accepted state only upon an actual -3; it never reduces the requested error accuracy. The divided minimum and the two carrier meshes change together in this comparison. Do not call it a one-factor error attribution.
4. Separately acquire the 49 low modes on the unchanged original engine with bank.py low fine seed, bridge, source heavy 1200, source heavy 1500 and source cold 225. Run stiffness.py for a local drag-stability diagnostic using the original tableau. No galaxy occupation or forest measurements are assumed here.
5. For each source archive produced, run gas_cases.py BAND MESH CASE TAG. Then assess.py 1, bands.py 1, contrast.py, low_controls.py, noise.py, amplitude.py, newton.py 1 and newton.py low. The low response uses one early carrier mesh but two independently prepared heavy interfaces, cold, and separate source/time/spacing tests. The low bank is not mislabeled as two native meshes.
6. For the unheated fully coupled switch control set MTS_FOREST_INDEX=1, MTS_FOREST_SCALE=0.01 and MTS_PRIVATE_FLOOR=32 in the parent shell. Run live_switch.py 1 on heavy, off heavy, off cold and on cold, setting MTS_FOREST_FACTOR to 1 for on, 0 for off, separately for each invocation. Clear the three switch variables before live_switch.py score 1 or normal circulation. Inspect the initial binaries and exact cold null in addition to the numerical errors. This control is not a nonlinear gas simulation.
7. Run cold_comparison.py then forecast_controls.py for the separately prepared rolling-cold baseline and independent four-dimensional estimator basis. Run local_susceptibility.py and tidal_susceptibility.py for the driven Klein–Gordon check and the phase-dependent Ricci source. These read existing sources without requesting a new galaxy preparation. The four live-switch nodes are indices 0,4,8,16; a three-node control is incompatible with the native matching table.
8. See RESULTS.md for which comparisons are supported; it is possible for pointwise relative errors near a zero to fail even when an absolute error is small. verify.py --seal on a complete, new stage records checksums and verify.py compares them against a fresh reread. The publication-facing records and the older source and result trees are not edited. The working resume bookmark lives outside the sealed stage.

Survey provenance: the likelihood and covariance used here are identified by asset-level Git and SHA-256 hashes in the previous forest-transfer release.json. Original forest measurements: https://arxiv.org/abs/1306.2314 ; likelihood: https://arxiv.org/abs/2206.08188 . A prospective extension with a different estimator is https://arxiv.org/abs/2108.10870 ; its bin windows, overlaps and nuisance terms must be checked separately before use. No observational likelihood for the heavy branch is computed in this stage.
