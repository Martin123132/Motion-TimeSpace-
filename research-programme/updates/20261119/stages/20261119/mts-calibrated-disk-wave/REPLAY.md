# Private replay

Use the retained Python with NumPy/SciPy from this directory; run with -B. No network or installation is required. Do not remove or overwrite the original stationary preparations. The initial chronological forecast and table sources are in FORECAST-FREEZE.md and SOURCES.md.

1. Branch creation, only if recreating in a separate appropriately located working copy: `python -B branch.py TAG SEED ETA SPEED`. Use these rows: main/disk20-diff/1/224.03, outer/diskbox-diff/1/224.03, above/diskbox-cap/1/224.03, coarse/disk12-diff/1/224.03, light/disk20-diff/0.9/224.03, heavy/disk20-diff/1.1/224.03, slow/disk20-diff/1/222.12, fast/disk20-diff/1/225.94. Existing carry-forward hashes are checked. Each packet has a path and forecast grid. Mass is in solar masses; halo normalization is relative to the inherited reference.
2. From these packets: `python -B force_tests.py`; `python -B compare.py`; `python -B tangent_check.py`; `python -B annulus.py`. No random seeds or fits to the compared data. The table writers compare with existing bytes rather than altering them. Matrix-library changes can affect least-significant digits; do not rewrite a sealed packet to make a reconstruction pass. In grid files positive vertical numbers are force-equivalent solar masses/pc²; vertical.csv gives signed physical force. In plane gR is inward at x=−R; vertical gz is signed upward. All g components use (km/s)²/kpc. Secant/derivative errors are scaled to peak within a given observable where indicated, not relative to each nearly zero derivative.
3. `python -B verify.py` checks the already sealed result. It checks the predecessor seal and all listed files, local hashes, input cases, locations, initial freeze, normalization constraint tangents, training-point identity, matched force and speed reconstruction, numerical controls and intended coarse failures. `verify.py seal` is only for initial sealing. No external data, inference service, running server, timer or GUI is required.
