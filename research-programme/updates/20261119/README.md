# Verified MTS work through 19 November 2026

Start with the [scientific status and limitations](../../../docs/status/STATUS-2026-11-19.md). This is an additive update to the [November 7 release](../20261107/README.md). It includes checked calculations that failed their physical targets as well as those that passed them.

**Browse by stage date:** [Nov 7](catalogue/20261107.md) · [8](catalogue/20261108.md) · [9](catalogue/20261109.md) · [10](catalogue/20261110.md) · [11](catalogue/20261111.md) · [12](catalogue/20261112.md) · [15](catalogue/20261115.md) · [16](catalogue/20261116.md) · [17](catalogue/20261117.md) · [18](catalogue/20261118.md) · [19](catalogue/20261119.md). These are stage labels, not dates of astronomical observations. [Stage index](stages.csv) · [release counts and exclusions](release.json).

Each stage directory provides a readable result, its available derivations, small evidence packs and numbered inventory files. Each inventory lists the original relative source name (an opaque identifier for an outside reference), the SHA-256 declared by the stage, and either the exact public location/member or the exclusion reason. Open or download the numbered evidence ZIPs to see the original paths inside; GitHub's web diff is not a file inventory. Result notes are historical: relative references inside them refer to their original calculation tree, not necessarily to files placed beside the public Markdown. Downloading and unpacking a stage's packs into one directory restores the selected original relative paths.

**Publication boundary.** Only declared artifacts from closed stages recorded in the research restart history enter the inventory. Original published files were rehashed against the local seal. Explicitly marked `.public.md` reading copies omit machine-specific or private operational passages and have separate original/public hashes; they are not bit-identical originals. Raw third-party inputs, builds, most large arrays, runtime material, private handoffs, and unsealed work are not part of this compact release. For example the LMC archive is linked at its [author's repository](https://zenodo.org/records/8015660), not redistributed. Omitted hashes are declarations of the source seals, not a fresh verification of every local-only array. This is not an entire-machine backup or a guarantee of standalone replay.

**Verify without relying on a potentially truncated GitHub listing:** from a clone after fetching the release, run `python tools/verify_release_20261119.py --rev HEAD` at the release commit (or supply its merge SHA). It traverses the Git tree, checks the [index of SHA-256 parts](ROOT-SHA256.csv), verifies every evidence pack and every included member, and checks source-record counts and directory sizes. No third-party dependencies or research datasets are required for integrity verification.
