# Private replay and source handling

Use the retained Python 3.13 scientific environment (NumPy/SciPy/h5py/requests), Python -B, one numerical thread. All paths are relative to this stage. The predecessor is hash-pinned. None of these programs writes to a predecessor. Do not re-download the eight sealed stellar packets for normal replay.

1. weights.py freezes the two 590 label maps using the existing launch and terminal aggregate archives. particle_currents.py uses previously saved shell positions and velocities. stellar_source.py was the one-time public acquisition: the earlier full-field-span method fetched noncontiguous chunks inefficiently and hit the transfer cap **before any packet was accepted**; the successful reader combines only neighboring physical HDF5 chunks and uses a per-piece cap. The eight successful receipts record ~852 MB, not failed-attempt traffic. In addition to the originally listed fields, formation times check which objects are genuinely new, and 590 velocities give the global virial velocity control outside the old aperture. Archived coordinate, mass and 590 velocity hashes match. Only the radial/polar components of the global velocities are retained; the earlier full 3-D velocities are used for the guard sample. Fresh acquisition requires a future explicit UTC deadline less than four hours away.
2. point_test.py launch runs on the launch packets and saves the actual-position instantaneous predictions. transport.py globally matches stellar triples and saves a compact endpoint-to-launch index plus mass banks. material_readouts.py scores the fixed inputs in the original cells and makes endpoint potentials. point_test.py endpoint independently evaluates the measured endpoint locations. Do not recompute or tune the launch weights from endpoint errors.
3. wave_response.py advances both waves; wave_response.py --refine additionally runs 16/32 substeps for the original and fine surviving-star cases. The eight-substep waves are the fixed orbit-driving endpoints. paired_star_orbits.py runs the two test-particle force grids. These are one-way test stars; do not report them as a live self-consistent galaxy.
4. audit.py --seal checks inputs, identity coverage, measured births, mass accounting, weak readouts and numerical comparisons; recreating outputs in the original environment checks existing bytes rather than replacing them. The manifest includes the source packets, local scripts, notes and results. No background service, schedule or publication is required.
