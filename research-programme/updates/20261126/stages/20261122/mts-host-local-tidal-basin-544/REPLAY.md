# Offline replay

No public repository or new installation is needed. Run from this stage with the retained Python 3.13, bytecode off, assertions **on**. The acquisition scripts prefer their saved inputs; genealogy.py reads the tiny cached HDF slices instead of the public multi-GB tree. Keep the prior sealed sibling stages, the host.dll and its GSL libraries in the locations pinned by fields.py and native.py. The centre-coordinate files for the three anchors live in their pinned parent inputs. Comparing the copied files does not substitute for recomputing the physics.

In order: acquire.py, products.py, genealogy.py, frame.py, topology.py, smooth.py, tilt.py, occupation.py, boost.py, speed_range.py, controls.py, verify.py. Use `py -3.13 -B filename.py` for each; one worker suffices. All output writers check existing artifacts before any creation and reject mismatched bytes. Tree and catalogue identifiers are checked at the three anchors, and the intervening descendants checked from the actual tree. Exact CSV and JSON replay is expected on the originating software stack; changes of linear algebra library can change low-order floating digits. Raw data URLs, hashes, camera rotations, epochs, and source convention are in the source ledgers and method (not bundled here).

Planned tests were fixed in [geometry protocol](PROTOCOL.md) and [occupation test](OCCUPATION-TEST.md). The angular boost extension and continuous-speed certificates follow the radial result: phase redistribution among harmonics is not itself loss of occupation. These are analytic/numerical sensitivity tests, not fresh observed data or a withheld-sample validation. The analytic finite-box control originally expected a nonzero lower bound for short support. It returned zero despite positive exact occupation; we kept that result, tested an enlarged support separately, and did not change the physical comparisons. The boosted large-support box also returns a zero bound. No process, timer, preview or service needs to persist.
