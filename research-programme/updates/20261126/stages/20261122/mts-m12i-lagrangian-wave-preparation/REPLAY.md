# Local replay and ownership

This directory is private. Do not put its large redistributable source/cache in a public release or send it to another chat. No GitHub operation or live fit. Published raw data belong to the FIRE collaboration; data citation references in RESULTS.md. The original GADGET binary is 4,407,283,216 bytes, SHA-256 04577b52c2fc8b4dfb15ea7c4fb5c336787f443c39505ae328fd3eb0a4bd0144. It remains in raw-cache for future local calculations. All IDs, sampled flags, source URLs, hashes, original units and hosts are retained; no full later snapshot was downloaded.

Use Python 3.13, -B, one numerical thread. Acquisition scripts: census.py reads the three dark fields of all four 544 shards, initial_file.py caches the named original IC and its supporting text; lineage_check.py reads headers plus spaced blocks from the four 001 shards. early_check.py also retains the small run parameter file. The rejected_slot_zero.py collector was stopped by its original count check before reading any particle rows. Its default entry point now simply verifies the saved rejection. The first attempt to obtain 001 sampled whole fields and exceeded the inherited per-shard transfer limit; it wrote no incomplete sample. The completed verification selects 16 deterministic distributed native chunks per shard and every eighth row within each; it is a cross-identification test, not uniform random inference on host mass. The 544 census and IC membership measurements themselves are complete, not estimated from this sample. The shuffled comparison is an identity null, not an MTS-vs-CDM validation sample.

Outputs can be checked without network or compiler using seal_stage.py. To reproduce the numerical outputs, first protect the original inputs and run destination.py, early_check.py and trace.py. The Windows C++ build for the two mass-assignment routines is from a 64-bit MSVC developer prompt, within this stage: cl /nologo /O2 /Fo:raw-cache\assignment.obj /LD mass_assignment.cpp /link /out:raw-cache\mass_assignment.dll /implib:raw-cache\mass_assignment.lib. No installer or background service. Then run assignment.py, tag_windows.py, matched_modes.py, direct_modes.py, verdict.py. assignment.py internally tests a wrapping two-particle example against independent Python arithmetic. The large raw cache and the 12 computed compressed Fourier meshes/windows are protected by content digests. Previously existing complete products are reused; to reproduce from scratch use a separate stage copy beside the same sealed parent input folders, preserving the original. Never remove a completed packet to bypass a mismatch.

The original model transfers are the hash-pinned 10 November volume-corrected formation packet and 20 November seeds interface; no new mass, cosmological parameter, curve or observational score was imported. The FIRE normalization check is derived independently from σ8: compare P(k=h)h³/[T(h)²(2π)³] in physical Mpc with MUSIC's logged pnorm for k_h=1. This is a transfer normalization check, not proof that nonlinear particle density is the generating Gaussian mode. Algorithmic source comparison: [MUSIC transfer plugin](https://github.com/lue/music/blob/8c8ff7bb10767e35efc19dcb669d6f106d388c41/plugins/transfer_eisenstein.cc); the comparison commit is not claimed to be the exact binary used in 2017. The run log and binary are primary. No live workers required to read the results.
