# Replay and verification

In this stage use Python 3.13 with NumPy and SciPy, -B, one OpenMP/BLAS thread, and the existing sealed parent folders. Run `py -3.13 -B verify_stage.py` on the saved checkout. The verifier checks the complete local manifest, signed inputs, the failed and passing gates and recomputes key scores from stored arrays. No downloads, native builds, publication or research runs are needed to verify. Do not rerun generators into the sealed directory. No oracle is needed for the frozen forward microscopic source; the independent comparison and the explicitly conditional repaired-background experiment do use later native data.

In a new isolated run, the sequence is source_bank → initialize_replay microscopic → native_tables → native_control → initialize_replay response → joint_run → score_native (each is a Python script). The initializer executes only the original frozen method receipts, not the obsolete failing runs. native_tables retains the per-leg background rather than treating the 782 starting values as a scalar. The original propagate_native entry produced the p16 /640 controls, but stopped at the /1280 join. joint_run is the production entry using a single, bit-identical Cauchy sample for both directions after verifying that the disagreement of the old past and forward contractions is at roundoff (<16 binary64 epsilons on the source scale). All eight production runs used that join; the two initial control packets are not mixed into the forecast.

single_history and harmonic_audit separate temporal vs angular effects and produce the auxiliary memory erratum. energy_channels and score_channels produce the exact spatial-energy split at original knots. shear_predict, check_shear and shear_seam test the independent shear route; it does not get a downstream pressure run because one original native mode fails. The single-orientation source packets and all forecasts are frozen before their comparison readouts. Later error attribution and the controlled repair were not blind tests on unseen data.

direct_shear uses the inherited temporary native compiler and the installed canonical CAMB fork on one continuous 24-mode block. The baseline native precision completed on 160 and 320 samples/Mpc. A stricter IntTolBoost=12 failed in DVERK before the first requested epoch; 24 was not attempted. No retry, missing row substitution or fabricated full freeze. The successful runs also emitted a background Romberg tolerance warning; retain that limitation. score_direct verifies the successful cases, with the intentionally checked incorrect total-anisotropy normalization superseded by the exact coefficient-one check in conservation_balance. conservation_readout adds density/background data and verifies common channels against the original callback. sector_readout uses the same block and clock in the cold and MTS models. conservation_balance, separate_conservation and repair_background implement the work and controlled repair. No generated readers, compiler mounts, app servers or rescheduled jobs are needed to retain the results.

The registered scenarios, including misses, are in RESULTS.md, PROTOCOL.md, SHEAR.md, DIRECT-SHEAR.md, CONSERVATION.md, SECTORS.md and ERRATUM.md. Keep the erratum linked when reporting the earlier memory diagnostic. Treat the raw banks and diagnostic binary packets as local reproducibility material; any repository update should follow the existing verified release policy, not stage the whole local directory blindly.
