# Replay without touching the earlier checkpoint

Use retained 64-bit Python 3.13 with NumPy and SciPy, in this folder, one numerical thread. No service, worker or download is needed for reading the results.

1. `python -B verify.py` verifies the saved accepted and rejected files against their distinct inventories, scientific checks and all 99 unchanged immediate parent files. The [protocol](PROTOCOL.md) fixes the source definition, controls and acceptance before interpreting the signs.
2. `python -B linear.py`, `python -B switch_budget.py`, `python -B launch.py`, `python -B cloud_stress.py`, `python -B mass_current.py` reconstruct the numerical tables. Existing products may only be matched, not overwritten.
3. The original native readout is acquired by `python -B native_source.py heavy cold`; the original solver, the 2026-11-07 observer, the matched spectral sources and the prior states are hash-checked. This reuses the sealed native chunks if present. The pressure experiment uses the independently built serial library. From a new Python process for **each** tuple run `python -B switched.py MODEL BOOST FLAG` with heavy/6/{0,1}, cold/6/{0,1}, heavy/7/{0,1}. 0 retains pressure; 1 suppresses it after the launch output. The original DLL and original source files stay in place unchanged.
4. `python -B build_switch.py --check-rebuild` compiles the two changed Fortran units in its own temporary folder, linking the remaining retained original objects; the numeric comparison executes the four primary native outputs against the archived results. The temporary compiler directory and its toolchain junction are removed after the children exit. Relinking on Windows need not give byte-identical *executable files*; the archived executable itself is hash-pinned. Model functions and changed lines are identified by exact source anchors, and their build inputs are recorded.
5. The first experimental build retained parallel dispatch with a shared per-mode switch. The equality/pressure-at-launch gate **rejected** it. Its DLL, build receipt and no-removal output are kept as diagnostics only and are not used for any numerical result. The accepted variant serializes the dispatch itself, not just the shell thread preference. The tighter boost-7 run also emitted a ROMBERG tolerance warning (integral ≈192.57608, reported error 7.04×10⁻¹⁴ vs requested 6.83×10⁻¹⁵); it is a precision cross-check, not exact arithmetic. The full primary and tighter differences and the failed outer relative tests are retained rather than scored as passes.
