# Local reproduction

Use the same Python 3.13, NumPy, SciPy, h5py and requests environment as the five-knot parent (not bundled here). Use -B, one numerical thread per job, at most two concurrent jobs. Source origin, citation, units and the fixed-axis transformation are documented by that parent. No fit, GitHub action or change of past files is required.

1. For the original-satellite question only: run python -B replay.py in the sibling mts-lmc-axisymmetric-retarded-replay-20261120 folder with no write flag. It reconstructs 12 wave/density histories, uses both model controls and checks all 192 force rows. The saved JSON is pinned by verify581.py.
2. For the new source test: the forecast and reference probability were sealed in the five-knot parent (next-forecast-lock.json). local_581.py takes a list of piece numbers 0 through 3. On the sealed products the receipt and bank are sufficient; do not redownload to verify a force. source_check.py checks the two forecasts against the actual source before transferring it. The raw field has no sky-fit role.
3. continue_wave.py joint 32 anchorA cut1 cut2 and the same at 64 use all-gas plus star source snapshots 572,579,581,586,590,600 with the exact 579 restart for the matching resolution. Use repeat5 64 anchorA for a negative control. The raw host uses raw_actual, raw_linear and raw_cold_detail at both 32 and 64 on anchorA; retain the common final raw-host potential, occupation, phase history and self-field. Predictions and actual source may differ by a spatially constant potential. Use density, forces and phase-aligned state distance rather than an absolute terminal phase.
4. inheritance.py checks source-direction and entry bounds. initial_gap.py checks transverse initial-state stiffness and independently tests the compensated energy identity. free_bound.py applies the named five-knot energy verifier only to the local joint packets, not the raw simulation or original LMC packets. All inherit unchanged matrix positivity and comparison conventions.
5. python -B verify581.py --seal checks parent files, four particle receipts, weighted forecast errors, all 13 restart packets, every local band decision and both initial and free-energy bounds. A second run checks the sealed bytes. Most products are write-once and will reject nonidentical replacement; use a separate directory for genuinely different experiments. A passed archive hash is distinct from a passed resolution test.
