# Replay and data provenance

Private working directory; never run a fit or touch the public repository for this checkpoint. Python, h5py, NumPy, SciPy and requests; one numerical thread, maximum two independent workers. Commands below use python -B. File writers refuse to alter a different existing product. Source download receipts individually pin content hashes of decoded arrays and of compact banks, exact remote object sizes/identity, all four part counts and byte traffic. They are not hashes of unrelated unread portions of the remote files. The two-dimensional mass banks, rather than raw multi-GB snapshot copies, are sufficient for offline reproduction of the comparison.

- Simulation authority and license: [FIRE-2 public release](https://astrosims.flatironinstitute.org/fire), [m12i core data](https://users.flatironinstitute.org/~mgrudic/fire2_public_release/core/m12i_res7100/), [Wetzel et al., DR1](https://arxiv.org/abs/2202.06969), [Wetzel et al., m12i](https://doi.org/10.3847/2041-8205/827/2/L23), [Hopkins et al., FIRE-2 physics](https://doi.org/10.1093/mnras/sty1690). Simulations use GIZMO; distributed data licensed CC BY 4.0. See release documentation for DR2 (Wetzel et al.) and GIZMO (Hopkins 2015). Here the observation-independent input is simulated ordinary matter in a CDM cosmology, not a measured history of the actual Galaxy.
- For the separate published disk-only cadence check: [Arora et al., potential models](https://web.sas.upenn.edu/dynamics/data/pot_models/) and the distributed 10kpc coefficient / coordinate files at the m12i URL. Its stellar+cold gas archive excludes hot gas; never import its mixed dark-matter/hot-gas halo. Snapshot times and center units are as supplied by FIRE. 
- collect_particles.py SNAP:PIECE … (0–3 for each of 572,579,586,590,600). Reads only the required authenticated-by-content local receipts or explicit HTTP ranges on publicly released HDF5; all gas and star masses and positions, no velocities, observed forces or raw halo particles. Histograms include fixed-axis and instantaneous-axis frames. Full counts include particles outside the 500-kpc science aperture. No source particle was silently substituted for a missing piece. No smoothing-temperature or star-formation-rate threshold. Byte-range reads are limited in size; no remote execution.
- Run joint_field.py 572 586 600; holdout_history.py freeze; then joint_field.py 572 579 586 590 600; holdout_history.py check. The prediction lock uses only the three coarse source fields and the published epochs. Never fit interpolation coefficients to the held-out fields. cadence.py uses 29 small stars+cold-gas files for a second source check; its diagnostics cannot substitute for all-temperature checks. gravity_controls.py and tilt_signature.py accept the epoch list: run for the three- and five-epoch series to check the Newton kernel, field-exchange identity and axis projection. The supplementary two-epoch source merge 579 600 just reuses the same inputs.
- response.py SOURCE STEPS EPOCHS BRANCHES, where EPOCHS is comma-separated. Main joint source: test 32 and 64 time steps per wave unit, anchorA cut1 cut2, on both three and five epochs. Diagnostic SOURCE monopole, rotating, coarse, quadrature: anchorA, 64 steps on both histories. SOURCE raw_total evolves anchorA's same wave occupation on actual simulated baryon fields with its own terminal and initial equilibria, at 32 and 64, reporting internal acceleration changes and **no observational score**. Never add a wave perturbation computed on an incompatible earlier preparation. A case's saved complex states allow local follow-up.
- The conversion_null control on the coarse history transfers gas to exactly co-spatial stars on the measured branch (64 steps per wave time). score_mesh.py processes the completed matrix. energy_gate.py checks terminal energy against the retained force barrier, solves the new zero-tilt compliance and uses both endpoints of the positive matrix pencil. validate.py rechecks the upstream sealed package, per-piece inventory, source arrays and branch/control comparisons, then writes a stage inventory. Repeating validate.py checks content integrity, not independent physical replication.
