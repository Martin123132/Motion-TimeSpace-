# Preserved development failures and refinements

No earlier sealed stage was edited. The following events occurred in this new,
unsealed daughter during implementation; they are not hidden physics exclusions.

- Build1: the portable compiler could not locate its Fortran frontend through
  the long Windows path. A temporary, automatically removed R: mapping and
  explicit compiler search paths solved the problem.
- Build2: the native SelfPointer override required the exact upstream argument
  name. Corrected the interface rather than changing the parent interface.
- Builds3–4: linking could not locate the runtime spec file. Added the portable
  compiler's actual library directories. No global installation was changed.
- Build5: linking succeeded, but the Python interface could not find the expected
  native method symbols. The exported method names were corrected in Build6.
  Build5's unusable binary was replaced before any physics run; no copy of that
  binary was retained. Its build report records the historical compilation only.
- Build6: passed the cold controls and first early evolution. Its binary and
  pre-change time-evolution source are preserved in runs/build-6, because the
  initial cold/background reports record that binary's hash.
- early-refined: a deliberately earlier start initially exceeded the thermal
  table's lower time boundary. The table initialization now honors the same
  earlier-start factor. Build7 contains that fix. The observed native error was
  `thermo out of bounds`; this process exited before producing a status report.
- Ordinary-resolution early runs were numerically complete but underresolved.
  Increasing perturbation accuracy alone did not remove starting-time sensitivity.
  The native time-to-scale-factor interpolation was only accurate to about
  1.6e-6 fractionally and blurred rapid background oscillations. Resolved native
  background grids remove that error. Those exploratory results are not the
  authoritative heavy-field state.
- Applying a very tight tolerance globally caused Romberg warnings for a
  full conformal-age integral: an approximately 3.23e-10 Mpc numerical residual
  exceeded an unnecessarily tiny requested tolerance. Final runs tighten the
  perturbation evolution separately, use sensible background/time tolerances,
  and have no native warnings. The earlier results are retained for diagnosis.
- First validation: rejected a non-contiguous NumPy view at a native API boundary.
  An explicit contiguous conversion fixed the checker, not the physics.
- validation-v2: 44 of 45 checks passed; the pressure projection failed the
  unchanged 2e-6 mode-normalized gate. A projection-order/window sweep found
  leakage from insufficiently represented oscillatory envelopes. Increasing
  the secular/harmonic polynomial orders to 6/4 and testing 8/6, across half
  windows 4pi, 6pi and 8pi, brings ALL six refined projections below the SAME
  gate. This is estimator convergence, not a fitted pressure coefficient.
- Domain-rejection runs intentionally fail when asked to evolve heavy
  perturbations past a=.00028. The matching event has not yet been implemented,
  so returning a late spectrum would be incorrect.

Authority: results/validation-final/status.json and
results/resolved-projection-analysis/status.json, not earlier exploratory packets.
The pressure residual is normalized to the density/velocity mode scale, not
to pressure itself. Tiny pressure can still have a large fractional correction.

For a future public release, package the native source delta and provenance,
not thousands of unpacked compiler/toolchain files. Source/compiler archives,
publisher checksum, and pinned source commits are retained locally. No GitHub
operation occurred in this stage.
