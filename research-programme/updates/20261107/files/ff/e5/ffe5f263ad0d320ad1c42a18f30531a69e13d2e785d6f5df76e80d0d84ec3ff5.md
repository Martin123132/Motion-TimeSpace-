# Stage201 execution and restart notes

This is a child of sealed Stage200. It consumes the completed half/quarter
histories at fraction 0.90625 and reuses all 36 existing virtual integrals at
x=14. The original scattering bank, grids, joins, temperature curve and
tolerances are unchanged. No public repository operation is involved.

## Two attempts, not one overwritten result

- The root `prediction/`, `actual/`, and `results/source-assessment.json` are
  the retained initial attempt. Its 276 strict reconstruction failures must
  remain visible. Passing its 1% tests did not qualify that attempt.
- `precision-representation/` is the separate coefficient-space precision
  repair. Its result is authoritative only if its unchanged assessment passes.
  Read `PRECISION-REPRESENTATION.md` for the mathematical equivalence and scope.
- `pilot/` is a post-test precision diagnostic. `cache-pilot/` verifies bitwise
  equivalence of the bounded-cache optimization to that repaired evaluator.
  Neither is a previously unseen physical holdout.
- Each attempt freezes all 36 increment predictions before its full absolute
  evaluation. The repaired attempt also preserves the original failed report's
  hash. This ordering does not undo the fact that the precision repair followed
  an observed numerical failure.

The selected source is evaluated directly from coefficient histories; the
absolute evaluator never reads or adds a frozen correction prediction.
Real/virtual/state contributions and photon/gas increments remain separate.

## Restart commands for this task

Run with Python 3.13, `-B`, and the working directory containing this file.
The scripts set one numerical-library thread and below-normal process priority.
Use at most one long numerical worker; do not interrupt unrelated processes.

    python -B cached201.py prediction --seconds 3600
    python -B repair201.py freeze
    python -B cached201.py actual --seconds 3600
    python -B repair201.py assess
    python -B compare201.py
    python -B finish201.py validate

Prediction/actual runs resume authenticated completed events. Do not run
`freeze` twice, or before all 36 prediction events exist. Do not assess before
all 36 absolute events exist. Do not rerun preparation or overwrite pilot files
after sealing. `progress.json` inside `precision-representation/` records a
safe event boundary. Event NPZ/JSON pairs carry hashes and runtime records.

After writing the results and next step, prepend the two resume headers while
preserving their archived bodies, then run `finish201.py seal`. A read-only hash
verification of the resulting seal is the final operation.

## Resource and scientific scope

All calculations are local, with no subagents or new loop integrations. The
cache is read-only and keyed by exact input arrays; each bounded cache is at
most 64 MiB. The full feature splines and source arrays use additional memory.
Cache hits do not replace altered inputs with nearby ones.

The four-hour check-in is measured from 15:04:45 Europe/London on 2026-10-23.
If the stage is incomplete near 19:04, save at the next event boundary and
report the exact completed count rather than losing work or calling it done.

This is a fixed-temperature numerical test of the retained linearized source.
It does not estimate missing higher-order physical terms or incoming-frequency
quadrature uncertainty. Those need the remaining frequency panel and subsequent
response test, not another repetition of a qualified x=14 calculation.
