# Stage204 execution and reuse

The new child reuses the sealed Stage202 runner and assessment functions via
Stage203 imports. Process-local bindings select the new child and frequency.
Stage201's coefficient-space evaluator and Stage200's histories are untouched.
Preparation authenticates the Stage203 seal, its payloads and consumed inputs.

The inherited assessment writes a two-frequency metadata header. The child
adapter replaces only that header with the declared scope frequencies, passing
all arrays and checks unchanged. Replay the qualified triple and require every
array to match bitwise before calculating any new predictions.

Use Python 3.13 with -B from this child:

    python -B source204.py prepare
    python -B assess204.py adapter-test
    python -B source204.py prediction --seconds 6000
    python -B source204.py freeze
    python -B source204.py actual --seconds 6000
    python -B assess204.py assess
    python -B finish204.py validate

Preparation/adapter-test happen once. Never prepare again or edit the frozen
protocol after prediction begins. Prediction/actual runs resume authenticated
completed event packets. Freeze only once, after all 36 predictions exist and
before any actual source event. The reference triple is never reevaluated.

Each event saves an NPZ/JSON pair with content hash, input identity, original
weight, checks and timestamps. progress.json records the event boundary.
A bounded driver may stop after an event; restart without discarding work.
If the four-hour check-in arrives first, prepend SAFE RESTART headers and run
restart204.py to retain an integrity ledger. It supports unfinished prediction
or actual phases; no qualified source claim is made from a partial run.

After a complete pass, write RESULTS.md, prepend both resume headers preserving
the archived old bodies, run finish204.py seal, and verify payload/bookmark
hashes. No parent files are edited and no virtual integrals are recomputed.
One long worker/thread, below-normal priority; no subagents or GitHub action.
