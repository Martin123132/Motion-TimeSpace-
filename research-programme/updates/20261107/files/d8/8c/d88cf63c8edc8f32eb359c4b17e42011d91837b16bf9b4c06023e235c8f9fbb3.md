# Verifier layout correction before execution

The first, unlaunched summary draft offered a fallback that guessed
the heavy pair was the last two core entries. That is not an authoritative
native layout. It was caught in source review before any summary launch.

summarize_v2.py instead reads the saved native signature, mapping and core
indices from the passing qualification context, following the exact
retained run_second.py construction. It records that context's hash.

The frozen draft is retained because some budget manifests may already
include its hash. It is not used for validation. The physical qualification
and budget workers always used system.slots from the native context;
their numerical work is unaffected. run_summary.ps1 launches only the
explicitly selected v2 verifier for the summary phase.
