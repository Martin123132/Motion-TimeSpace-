# Pre-target cache-state precision repair

The retained anchor audit finds a maximum 4.4806491238559737e-10 relative
high-mode state discrepancy against an 80-digit recomputation. Its existing
1e-10 reconstruction gate fails for some rows. The 60/80-digit comparison
is evaluated independently. The audited primitive energy, number and gas
rows use their prior 80-digit repair and are not replaced here.

Cause: a new virtual calculation sets the global mpmath precision to 60,
whereas a cached virtual coefficient does not. The high-mode state evaluator
inherits that global precision. At the cached anchor it was 15 digits.
This is a numerical execution-state issue, not a new physical term.

Before any target source evaluation or prediction freeze, recompute only
the state component at 60 and 80 digits on the unchanged saved events.
Store separate overlays, preserve every original bank file and failed audit,
and rebuild the remainder and total by adding the same components.
The frozen source prediction must read those overlays, not silently modify
the original bank. No temperature fit, event selection, band or tolerance changes.

The independent target worker starts explicitly at 60-digit state precision;
primitive moments still use their existing 80-digit repair. This removes
cache-dependent precision on restarts as well. Batch validation uses the
same explicit setting. The original driver is intentionally stopped at its
pre-freeze directory guard, then resumed through the corrected freezer.

One short state-only audit overlapped the single production worker.
There were at most two Python compute processes briefly, not two heavy
production jobs; both were below normal priority with numerical-library
thread counts set to one. No unrelated process was stopped.
